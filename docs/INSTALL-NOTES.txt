==========================================================
Claude Multi-Instance Setup  v1.1
      Run multiple Claude Desktop profiles on one machine
==========================================================

QUICK START
-----------
1. Double-click  Claude-Multi-Setup.exe
2. Pick how many instances you want (e.g. "Instance 2", "Work")
3. Click  Install
4. Open each new desktop shortcut and sign in separately
   - each profile is fully isolated (accounts, files, settings)
5. Done — all instances run simultaneously

TIP: If you already set up instances before, the wizard detects them,
pre-fills the list, and refreshes them without touching your profiles.

REQUIREMENTS
------------
• Windows 10/11  — Claude Desktop installed from the Microsoft Store or standalone
• Node.js 18+    — needed for the patching step (https://nodejs.org)
                    (only required on first install / after a Claude update)
• macOS / Linux  — build from source (see README.md); no patching required

WHAT THE WIZARD DOES
--------------------
Windows (MSIX / Store build):
  - Copies the Claude app to a shared location so it doesn't touch the
    original WindowsApps install.
  - Patches the Electron asar bundle so --user-data-dir is honoured
    (the 3P managed-config relocation block is bypassed).
  - Disables the asar integrity fuse on the copy so the patch survives.
  - Creates one .vbs launcher + desktop shortcut per instance.
  - Profiles live in %LOCALAPPDATA%\Claude-<Name>

macOS / Linux:
  - Generates .command / shell launchers that pass --user-data-dir
    plus the CLAUDE_USER_DATA_DIR env var.
  - Profiles live in ~/Library/Application Support/Claude-<Name>  (mac)
                                     ~/.config/Claude-<Name>       (Linux)

CLI MODE (no GUI)
-----------------
  Claude-Multi-Setup.exe --cli Work,Personal,School
  Claude-Multi-Setup.exe --cli --repair          (re-patch existing after update)

REINSTALL AFTER A CLAUDE UPDATE
-------------------------------
When Anthropic releases a new Claude Desktop version the Store/MSIX app
will be updated automatically.  The patched copy will no longer match the
new code.  Re-run the wizard (or run  --cli --repair  headless) — it
detects the new version and re-patches.  Your profiles and launchers are
preserved.

TROUBLESHOOTING
---------------
Q: Only one instance opens when I double-click shortcuts
A: Make sure you're clicking the shortcuts created by the wizard
   (named "Claude (<Name>).lnk"), NOT the original Claude shortcut
   pinned to your taskbar.  The taskbar pin must also point to the
   .vbs launcher, not the bare .exe.

Q: "Access is denied" during patch
A: Close all Claude windows first, then re-run.

Q: Patch says "Could not locate the relocation code"
A: Claude renamed its bundled patch target (DW/Cl -> FJ across versions).
   v1.1 of this wizard recognises all known layouts (Claude <=1.5x and 2.x).

Q: Exit code -36861 when launching
A: The integrity fuse is still active on the copied exe.
   Re-run the wizard, or manually:
     npx @electron/fuses write --app <path>Claude.exe \
         EnableEmbeddedAsarIntegrityValidation=off

Q: Both instances land on the same profile
A: Ensure the launcher sets CLAUDE_USER_DATA_DIR and passes
   --user-data-dir with the same path.  The .vbs launchers
   generated by the wizard do both automatically.

FILES CREATED BY THE WIZARD
----------------------------
  <base>\Claude-<Name>.vbs          launcher for instance <Name>
  <base>\ClaudeInstances\app\       shared patched Claude app (Windows only)
  <base>\ClaudeInstances\icon.ico   shortcut icon

  %LOCALAPPDATA%\Claude-<Name>\     profile data (config, auth, history)
  %APPDATA%\Claude\                 original / default profile

  Desktop\Claude (<Name>).lnk       desktop shortcut per instance
  TaskBar\Claude <Name>.lnk         taskbar pin per instance
